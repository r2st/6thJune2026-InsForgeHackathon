Hush.

Catches the bugs that don't make a sound.

Built on InsForge · powered by Replicas, Limrun, Devin, Vercel
01 · The problem

Most bugs don't crash. They just frustrate.

A button that does nothing when you click it. A form that says "saved" but doesn't save. A dropdown that opens behind the modal. None of these throw an error. Sentry sees nothing. The dev sees nothing. The user just leaves.

~70%

of user-reported bugs in modern web apps never throw a server error. They fail at the screen, not in the code path your error tracker watches. (Industry estimate from FullStory and LogRocket behavioural-bug studies.)

Today, finding these bugs means a customer emails support. Support pings engineering. Engineering asks for a repro. The user can't repro it. The ticket dies. Meanwhile the bug keeps shipping.

02 · The shift

Watch the user, not the stack trace.

Every silent bug leaves a trail in the user's session: rage-clicks, abandoned forms, repeated taps, fast back-button presses. Session replay tools already capture this — they just show the recording to humans. Hush lets an agent watch it, run the bug again on its own, and ship the fix.

// the current way

Sentry · Seer · Autofix

Starts from a stack trace. Great at fixing the bug that already broke production. Blind to every bug that didn't throw.

Hush

Starts from a session. Catches the broken button, the silent form, the dropdown nobody can click. The 70% Sentry can't see.

03 · How it works

Four steps. One platform.

A user gets stuck. Sixty seconds later, a fix lands in the repo with a video of the original bug attached.

Watch
Replicas
Spots a user getting stuck — rage clicks, abandons, or a "report bug" tap.
02
Run it again
Limrun
Boots a clean browser sandbox and replays the session as a test. If the bug is real, the test fails.
03
Diagnose
InsForge AI
Writes a plain-English bug report: what the user expected, what happened, what's likely broken.
04
Fix & ship
Devin → GitHub
Edits the code until the test passes. Opens a PR with the session clip inside.
InsForgethe platform underneath all four

Holds the memory of every bug, the live status of every run, the safe test data, and the multi-tenant access rules. Without InsForge, the loop is four tools shouting at each other. With it, they share state.

04 · What's new — confidence tiers

Don't always open a PR. Match the action to the certainty.

Every engineer's first objection to bug-fixing agents: "what if it opens a bunch of bad PRs?" Hush handles this directly. Before acting, it scores its own confidence using pgvector similarity to past, human-confirmed fixes. Then it picks the right output.

High · 85%+

Open a PR with the fix

The fix passed the test. Similar bugs in the past got merged unchanged. Ship it for review.

Medium · 60–85%

Open a draft PR — test only, no fix

The bug is real and we can prove it. We're not sure of the fix. Hand the failing test and the diagnosis to a human.

Low · <60%

Open a GitHub issue with the clip

Something looks wrong but it's not certain. File it, attach the session video, let someone decide.

This is the difference between a hackathon toy and a tool a real engineering team would install. It also gives us three different demos in one — depending on the audience, lead with whichever moment they react to.

05 · What's new — it gets smarter

Closing a PR teaches Hush.

When a dev closes a Hush PR as "not a bug, by design" or "duplicate," that signal goes back into pgvector. The next time a similar session fires, Hush recognises the shape and skips it — or drops it from PR straight to issue. Every rejection makes the next one quieter.

Sentry Seer can't do this. It doesn't have memory of this team's taste. Hush does, because InsForge gives it a vector store and an RLS-scoped data model out of the box.

06 · Why InsForge sits at the center

Five things, each load-bearing.

It would be easy to use InsForge as just a database. We don't. Hush leans on five distinct features — each earns its place because the loop genuinely needs it.

pgvector
Powers dedup, confidence tiers, and the "learns from rejection" loop. Bugs become embeddings; memory becomes the moat.
Branch projects
Devin tests the fix against a fork of the customer's real data. Safe. The kind of detail judges nod at.
Realtime
The receipt page streams every step live: captured → testing → fixing → shipped. This is the demo wow.
Auth + RLS
Multi-tenant from day one. Customer A never sees Customer B's bug stream. A real product, not a demo.
Storage + edge fns
Session clips with signed URLs (so PRs can embed them) and the whole backend as one insforge.toml.
InsForge AI
The diagnosis step calls InsForge's built-in AI gateway. The whole brain runs on one platform.
07 · What the judges see

A 60-second story.

0:00
A user clicks "Add to cart." Nothing happens. Split screen: their cursor on the left, the empty cart on the right. They rage-click. No error in the console. Sentry sees nothing.
0:10
The receipt page lights up. InsForge gets the Replicas webhook. pgvector checks: new bug. Realtime broadcasts "Session captured ✓ · Booting sandbox…" The user (and the judge) can see Hush is on it.
0:25
A test runs and fails. Limrun replays the session against an InsForge branch project. It clicks the button. The cart doesn't update. Red. Receipt updates: "Test failing · Diagnosing…"
0:40
Devin opens a PR. Green CI. InsForge AI writes the bug report. Devin edits a one-line CSS regression, reruns the test, passes. The PR description embeds the session clip from InsForge Storage. Confidence: 91% → open PR with fix.
0:55
"Sentry would still be silent. Hush shipped the fix in under a minute." Close on the GitHub PR. Judges can click through. The InsForge dashboard behind shows the audit row for the run.
08 · Build plan

Nine hours, seven checkpoints.

T+0h
Lock the demo bug. A toy e-commerce app with a broken "Add to cart" button (CSS regression). Pre-record one Replicas session as a fallback.
T+1h
InsForge backend up. One insforge.toml: schema with pgvector, RLS, Storage bucket, Realtime channel. Branch project forked. Demo app on Vercel points at it.
T+3h
Signal end-to-end. Replicas → edge fn → pgvector dedup → Storage clip → Realtime "session captured." Limrun boots, runs Playwright against the branch project. Test fails.
T+5h
Devin closes the loop. InsForge AI writes the diagnosis. Devin edits, reruns, passes. Edge fn opens the GitHub PR with the embedded clip.
T+6h
Confidence tiers. Score each run via pgvector similarity. Switch behaviour: high → PR, medium → draft PR, low → issue. Three demo paths, one loop.
T+7h
Receipt page. Next.js on Vercel subscribed to the Realtime channel. Status lines stream in live. Click-through to the PR works.
T+8h
Pitch + fallback. Pre-record the 60-second demo video for wifi failure. Rehearse 3×. 90-second cap.
T+9h
Demo. Open on the broken button. Close on the green PR with the InsForge dashboard behind it. Don't narrate architecture — let the loop close.
09 · If we have to pivot

Backups, collapsed.

Hot-swap order: Hush → DepWatch → SOC2 Pilot. Click to expand.

DepWatch

A morning agent that watches your lockfile for supply-chain risk. Same downstream stack as Hush — just swap session capture for lockfile parse.
Reuses the Bellwether deck architecture. Lower build risk; saves ~3 hours of design work. Use if Replicas blocks.

Migration Pilot

InsForge branch projects + blast-radius report before any migration PR opens.
Hits the InsForge sponsor head-on. Lower demo wow than Hush but unmistakably native to the primary sponsor.

SOC2 Pilot

Drop a security questionnaire URL; the agent fills it overnight with cited answers.
Same loop shape as Hush, different buyer. Use if the room reads less dev-focused than we expect.
