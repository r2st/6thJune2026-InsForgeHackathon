InsForge Hackathon · 6 June · Final pitch · v7 · post-analysis pivot

Hush.

Catches the bugs that quietly break your customers.

Built on InsForge · powered by Limrun, Devin, Vercel · rrweb in the app
Sentry catches the bugs that crash your server. Hush catches the bugs that quietly break your customers — silent RLS misfires, leaked tenants, vanished records — by replaying them on a forked InsForge backend, patching insforge.toml, and shipping the PR before the user has finished writing the support ticket.
01 · The problem

The worst bugs don't crash. They leak.

A logged-in customer opens "My Orders." The list is empty — but their orders exist. A different user briefly sees rows that belong to another tenant. A receipt URL returns 200 but loads a stranger's PDF. Nothing throws. Your error tracker is silent. Your support inbox is not.

These are silent backend bugs — RLS misfires, stale JWT claims, policy regressions, auth boundary drift. Most user-reported bugs never reach Sentry because they fail at the policy layer, not the code path. Today, finding them means a customer emails support, support pings engineering, engineering asks for a repro, the user can't repro it, the ticket dies. Meanwhile the bug keeps shipping.

02 · The shift

Trace the symptom to the policy.

Every silent backend bug leaves two trails: the user's frustration on the frontend (rage-clicks, refreshes, abandoned pages) and the corresponding decision in the backend logs (which policy ran, what it returned). Existing tools see one or the other. Hush correlates them. Then it fixes the policy, not the page.

// the current way

Sentry · Seer · Autofix

Starts from a stack trace. Brilliant at fixing the bug that already broke production. Blind to bugs where the response is 200 but wrong.

// hush

Hush

Starts from a session + backend log pair. Identifies the policy that misfired, drafts the insforge.toml diff, verifies it on a forked backend, ships the PR.

InsForgethe platform underneath all five

Holds the schema, the policies, the forkable test backend, the request log, the realtime status stream, and the memory of every prior bug. Without InsForge, this loop cannot exist on any other backend — and that is the whole point.

04 · The moat

Why this can only be built on InsForge.

Most agentic dev tools are platform-agnostic — they'd work on Supabase, Convex, Neon, anything. Hush is not. Two InsForge primitives are load-bearing; you cannot replace them with anything in the market.

Forkable backends + declarative auth.

To safely propose a policy patch, the agent must (a) run the patch against prod-shaped data and (b) compare the result deterministically. Both require forking the entire backend — schema, policies, auth — and running the same session against it. That's InsForge branch projects. And the patch itself is a diff against insforge.toml, which is small, structured, auditable, and within Devin's one-shot range. No other platform has this pairing.

Supabase

Has RLS. No branch projects. Patches are SQL migrations against shared infra. Risky to test.

Convex / Neon

Convex has no RLS layer. Neon has branches but no auth/RLS at all. Neither composes.

InsForge

Branch projects fork backend + auth + RLS together. insforge.toml is the declarative source of truth. Hush exists because of this pairing.

pgvector, Realtime, Storage, and InsForge AI are also used — but those are supporting roles. They're not what makes the product impossible elsewhere.

05 · What's new — confidence tiers

Match the action to the certainty.

Every engineer's first objection to autonomous PRs: "what if it ships a bad policy change?" Hush handles this directly. Before acting, it scores its own confidence using three signals: diff size, policy blast radius (how many tables / routes the patch touches), and pgvector similarity to past human-confirmed merges. Then it picks the right output.

High · 85%+

Open a PR with the fix

Small diff, single policy, branch project replays clean. Similar diffs were merged before. Ship for review.

Medium · 60–85%

Open a draft PR — trace only

Bug reproduces on the branch project. Fix touches more than one policy or changes a column. Hand the failing trace to a human.

Low · <60%

Open a GitHub issue with the clip

Something looks anomalous but the branch replay doesn't reproduce it cleanly. File it, attach the session video and the request-log diff.

This is the difference between a hackathon toy and a tool a team would let near production. It also gives us three demo paths in one — lead with whichever beat the room reacts to.

06 · What's new — it gets smarter

Closing a PR teaches Hush.

When a dev closes a Hush PR as "by design" or "wontfix," that signal goes back into pgvector. The next time a similar (session, policy, log) tuple fires, Hush recognises the shape and skips it — or drops it from PR straight to issue. Every rejection makes the next one quieter.

Sentry Seer can't do this. It has no memory of this team's policy taste. Hush does, because InsForge gives it a vector store + RLS-scoped data model out of the box.

07 · What the judges see

A 60-second story.

0:00
A logged-in customer opens "My Orders." Empty. They refresh. Still empty. Split screen: their screen on the left, the receipt page on the right (still dark). They've placed three orders this month. None are showing. Server returns 200.
0:10
The receipt page lights up. InsForge edge fn fires on the frustration signal. pgvector says new. Realtime streams: "Session captured · Backend log tapped · 1 anomaly."
0:20
A plain-English diagnosis appears. InsForge AI: "Policy orders_select reads tenant_id from auth.jwt() ->> 'tenant'. This user's JWT migrated to tenant_ids[] last week. Policy never updated. Likely fix: read from the array."
0:35
A branch project spawns. The TOML diff applies. The session replays. Orders appear. Two terminals side by side: prod (red — still empty) and branch (green — orders visible). The bug is gone on the branch. Proof.
0:50
Devin opens a PR. 4 lines of insforge.toml. PR description: the session clip, the before/after RLS trace, the branch project's run id. CI green. Confidence: 92% → PR with fix.
0:58
"Sentry is silent on auth bugs. Hush shipped the policy fix in under a minute." Close on the InsForge dashboard showing the audit row for the run. Judges can click through to the PR.
08 · Build plan

Nine hours, seven checkpoints.

T+0h
Lock the demo bug. A toy multi-tenant app with an orders table and an RLS misfire — one wrong JWT claim path. Pre-seed two users so the leak/filter direction is obvious. One pre-recorded session as fallback.
T+1h
InsForge backend up. insforge.toml declares: orders table + RLS, an edge fn that logs every request, a Storage bucket, a Realtime channel, a pgvector column on bugs. Branch project forked. Demo app on Vercel.
T+3h
Watch + Correlate end-to-end. rrweb in the toy app posts to an edge fn. Edge fn taps the matching backend log window. pgvector dedup checks. Realtime broadcasts "session captured."
T+5h
Fork + diagnose. InsForge AI writes the plain-English diagnosis from the failing log. Branch project spawns. Devin gets a narrowly scoped prompt: "propose a insforge.toml diff that satisfies this failing branch-project test." High one-shot success.
T+6h
Confidence tiers. Score = (diff size × blast radius × pgvector similarity). Branch to PR / draft PR / issue. Seed two demo runs at different scores so all three paths can be shown.
T+7h
Receipt page. Next.js on Vercel subscribed to the Realtime channel. Five status lines stream live. The branch-vs-prod diff terminal pair is the climax visual — not a GitHub PR. More InsForge-specific.
T+8h
Pitch + fallback. Pre-record the 60-second demo video. Use the branch diff view as the climax shot. Rehearse 3×. Hard 90s cap.
T+9h
Demo. Open on the empty Orders page. Close on the green branch + the PR. Don't narrate architecture — let the policy fix land on stage.
09 · If we have to pivot

Backups, collapsed.

Hot-swap order: Hush → Migration Pilot (closest) → DepWatch → SOC2 Pilot. Click to expand.

Migration Pilot

Branch-project blast-radius preview before any migration PR. Closest neighbour to Hush — could be merged if needed.
Same branch-project + insforge.toml primitives, but the trigger is a developer-authored migration rather than a user session. If the Watch step (rrweb capture) blocks, fold Hush into this — same demo wow without the capture dependency.

DepWatch

A morning agent that watches your lockfile for supply-chain risk. Same downstream stack as Hush minus the capture step.
Reuses the prior Bellwether deck architecture. Lower build risk, saves ~3 hours of design. Use if both rrweb and branch projects are blocked.

SOC2 Pilot

Drop a security questionnaire URL; the agent fills it overnight with cited answers.
Same loop shape, different buyer. Use only if the room reads less dev-focused than expected.

10 · What changed from v6

v6 → v7 reflects the critique in FINAL-analysis.md. Same shell (name, tagline, demo arc, confidence tiers, learning loop), different engine.

  • Pivoted bug class from "broken Add-to-cart (CSS regression)" → "silent RLS misfire on My Orders." Higher stakes, easier to fix, impossible to ignore.
  • Replicas → rrweb in the toy app. Removes sponsor-API dependency risk. Frontend capture is now ours to control.
  • Devin's job narrowed from "fix arbitrary React/TS code" → "propose a insforge.toml diff that satisfies a failing branch-project test." Far higher one-shot rate.
  • InsForge moat made structural, not cosmetic. Branch projects + declarative insforge.toml are now load-bearing. Survives "why not Supabase?" in one sentence.
  • Dropped the uncited 70% stat. Replaced with a directional claim and a concrete demo bug.
  • Demo climax shot changed from a GitHub PR view → a branch-vs-prod diff terminal pair. More InsForge-specific, more visceral.
  • Stage one-liner added at the top — a sentence a technical judge can't poke holes in.
